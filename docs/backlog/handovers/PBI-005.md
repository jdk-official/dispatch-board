## Three things worth carrying forward

**The round-1 High was a test that proved nothing.** `test_no_client_can_stall_another` read as proof of AC-SV10 and of spec-gate finding S-3, but the "stalled" client kept draining into the OS socket send buffer, so the queue never overflowed — the reviewer instrumented `queue.Queue.put_nowait` and measured **0 `queue.Full` events**. The entire drop path was untested and the test asserted nothing about the stalled client. Fixed by making the test force overflow, not by softening the criterion; round 2 re-measured **2 `queue.Full` events**, and an unbounded queue fails both tests.

**A real race.** `Hub.register` reused a watcher whose `stop` Event was already set, so a client connecting between the last unregister and the thread exiting got no watcher at all — live push silently dead, no error, self-healing only on a later connection. Probe before: clients=1, alive=False, 0 refreshes. After: alive=True, 11 refreshes, change delivered.

**A defect the repaired test surfaced, that neither review round had found.** CPython sets `request_version` only after its 505 and bad-version-400 checks, so it is still `HTTP/0.9` when `send_error` runs and the base class suppresses the status line and every header — the 505 returned a bare `bad request` with no `Content-Type`, `Content-Length`, `Cache-Control` or `nosniff`. `_respond_plain` now forces HTTP/1.1 there. The builder's worry that a genuine HTTP/0.9 client would get unparseable headers does not bite: CPython 3.14 gives such a request `headers = {}`, so it cannot pass the Host gate and receives 403 with no board data.

A plan defect, not a build defect; cheapest as a spec edit at the next revision.
