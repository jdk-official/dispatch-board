## What landed

The page reaches its data through an adapter chosen at load: the artifact store as before, or the local server PBI-005 landed. Both render the same board. The store adapter keeps its eight `window.claude.use('db')` subscriptions unchanged; the local API adapter fetches `/api/snapshot` and opens `/api/events?since=<version>`, applying `change` events in place and re-fetching on `reset`.

**The one design decision this PBI owned** — the parent spec's row Q-11 left the detection *signal* open — is the `window.__DISPATCH_LOCAL__` marker, not the absence of `window.claude`. An artifact published without its `db` capability also lacks `window.claude`, and that case must still show the store's out-of-reach board rather than silently reaching for a local server that is not there. Both marker URLs are required and must be same-origin.

## The milestone worth recording

**This is the first time the two halves of the local-first system ran together.** The builder started the real `local/server.py` over a real SQLite database and drove the page's inline script with its actual `/api/snapshot`. The round-2 reviewer repeated it headlessly and confirmed PBI-005's spec-gate finding **S-4 holds across the seam**: `reset` carries `id: <version>`, change events carry ids, and the server takes the larger of `since`/`Last-Event-ID` — so the reconnect loop that finding warned about cannot occur. Until now that was an argued guarantee on one side of an interface; it is now a measured one across it.

## Adversarial verification at round 2

- **19 hostile URLs** against the new same-origin check. Refused: the userinfo trick, `https://127.0.0.1:8765.evil.test/` (a prefix lookalike that defeats a naive `startsWith`), all three backslash-to-another-host forms, other-scheme, other-port, `file:`, `about:`, `vbscript:`, `data:`, `javascript:`, ipv6, and a foreign-origin `blob:`. URLs are validated, not rewritten, and there is no `<base>` element in the page or in `_wrap_page()`, so the validation base and the fetch base are the same.
- **The render hold releases on a throw** — a reader was forced to raise inside it; the `finally` unwound and the next event still drew. A leaked hold would have frozen the board.
- **No regression to the published board** — the eight store subscriptions are unchanged in shape, and `env()`'s throwing `fetch`/`EventSource` stubs make a mutant routed down the local path fail rather than pass.
- **No leak, no new XSS surface** — `answers/` and `collector_state/` records are inert, unknown collections are never read, no renderer was touched, `md()` was not widened, and an `img onerror` payload in a findings title arrives entity-escaped on both adapters.
