## Two things worth carrying forward

**A criterion was wrong, and was corrected rather than ticked.** R-1 named `local/records.shapes.json` as a file that must change. It contains zero occurrences of any tab name — it mirrors only the field spec — so that half of the criterion was satisfiable only vacuously. Verified independently by the orchestrator before the review, agreed by the reviewer. The criterion text is struck and annotated in the PBI rather than recorded as though both files moved.

**This widening created a cross-PBI hazard, caught at another gate before either built.** Once `TAB_NAMES` includes `findings`, it is no longer safe for any component to derive a "tabs this pass owns" set from it: `projectTabs` has two writers — `export_board` owns the five suffixes, `export_sessions` owns `findings` (PBI-011) — and each is forbidden to touch the other's. PBI-025's revision-1 spec did exactly that, and would have deleted the local `findings` record on every 60-second collector pass, destroying what PBI-011 publishes. Caught as finding F-2 at PBI-025's spec gate while both were still in flight, and fixed in that spec's revision 2. Anyone adding a name here should check for the same pattern elsewhere.

## Follow-ups

- `local/records.py:103` joins `TAB_NAMES` into the regex with no `re.escape` — inert today, since every name is alphabetic, but a fail-open trap for a future name carrying a metacharacter.
- `FindingsFixture.transcripts()` copy-pastes ~25 of 32 lines of the base fixture instead of extending it, so later edits to the base fixture will silently stop reaching the findings test.
